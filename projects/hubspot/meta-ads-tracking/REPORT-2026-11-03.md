## 3. HubSpot — what the Aircall integration exposes

Yes, the dialed number is recorded, in two places:

- On every logged call: `hs_call_to_number` ("To Number"). Peter's two test calls to the
  new line (Oct 29 and Nov 3) show +18052736775. Those are the only two calls ever logged
  to that number.
- On the contact: `last_used_aircall_phone_number` ("Last used Aircall phone number"),
  which Aircall rewrites after each call. Note it is "last used": if Dio later calls the
  person back from the Office Line it flips to +18052881119. The rule below therefore
  tags once and never relies on the value staying put.

How Office Line callers are tagged today: Dio sets the contact's `import_type`
("import type") to "Direct Phone Call"; the Lead Source backfill mapped that to "Phone".
Lead Source itself is required on every new deal (Dio picks it on create).

### Proposed rule (dry run — not built)

HubSpot contact-based workflow "Meta Ads call → import type":

1. Enroll when "Last used Aircall phone number" is equal to +18052736775.
   Enroll future contacts only (do not enroll the two existing matches, see below).
2. If "import type" is empty → set it to a new option "Meta Ads".
   If "import type" already has a value → do nothing (never overwrite).
3. Lead Source on the deal: Dio sees "import type = Meta Ads" on the contact and picks
   "Meta Ads" when he creates the deal (required field). Add one row to the contact-import-
   type → Lead Source mapping: Meta Ads → Meta Ads.

Prerequisite write: add "Meta Ads" as an option to the contact `import_type` dropdown.

Optional backstop (not recommended for now, keep it simple): deal-based workflow — on
deal create, if the deal's contact has import type "Meta Ads" and Lead Source is blank,
set Lead Source = Meta Ads. Lead Source is required on create, so this rarely fires.
